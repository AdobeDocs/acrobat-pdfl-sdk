# RST → Markdown Conversion Plan

Project under change: `C:\GIT\format_conversion\dev.adobe.com_rst2md_project\rst2md_converter` (separate git repo).

- Input: `rst2md_converter/input_rst` (122 `.rst` files, standard RST)
- Output: `rst2md_converter/output_md/source` (currently 106 `.md` files, standard GFM markdown, consumed by MkDocs → HTML)

## 1. Existing pipeline (as found)

Five ordered scripts in `rst2md_converter/python/`:

1. `1rst2md.py` — core converter. Parses RST via Sphinx into a doctree, renders it to Markdown with a custom `MarkdownRenderer` (headings, lists, tables, images, admonitions, refs). Also pre-normalizes malformed RST grid tables (mismatched column widths) before Sphinx parses them. Writes `conversion_report.json` and validates internal links/anchors.
2. `2rename-files.py` — normalizes output filenames (lowercase, safe chars), rewrites links/refs to match, deletes generated `toc.md`/`toc.rst` stub pages.
3. `3create-yaml-toc.py` — builds MkDocs `nav:` from `input_rst/toc.rst` + per-section `toc.rst` ordering.
4. `4fix-tables-without-header.py` — **diagnostic only**, does not fix anything despite the filename. Scans output `.md` for pipe-table-looking blocks whose 2nd line isn't a GFM separator row (`| --- | --- |`), prints them or writes an HTML index.
5. `5clean-markdown.py` — cleanup pass: strips stray HTML anchors, re-aligns separator-row dash widths to header width, converts `<br>-` bullet sequences inside table cells to `*`, trims stray spaces before `,`/`)`/`.`.

Only `1rst2md.py`'s output represents current renderer behavior. The 106 files in `output_md/source` today were committed by an earlier version of this pipeline (single commit `22913e1`, "still need to add frontmatter") — they are **stale relative to the current scripts** and may not reflect what a fresh run produces.

## 2. Diagnosis of the table issue

You suspected a missing blank row between header and body — that's not the correct GFM rule (GFM needs a `|---|---|` separator row, not a blank line), but the underlying suspicion (some tables are malformed) is confirmed:

Running `4fix-tables-without-header.py` against the current `output_md/source` finds **29 pipe-table blocks with no valid separator row**, of two distinct kinds:

- **Real defects**: multi-row cells from RST tables (e.g. `pdlflibapi_pdfl_dictionary_keys.md`) where each physical line of a table row became its own separate pipe-row block instead of being merged into one row with `<br>`. This is consistent with content generated by an *older* converter than the current `1rst2md.py` (whose `_escape_md_table_cell` already collapses embedded newlines to `<br>`, so a fresh run should not reproduce this).
- **False positives in the detector itself**: `pdfmark-examples.md` lines 521-522 are a fenced PostScript code block containing literal `%`/comment lines that happen to start with `|`-like content — `4fix-tables-without-header.py` doesn't skip fenced code blocks (unlike `5clean-markdown.py`, which does via `_apply_outside_fenced_code_blocks`), so it misreports code as a broken table.

Conclusion: before touching the renderer, we need to know whether a **fresh** run of the current pipeline on `input_rst` still produces broken tables, or whether the defects only exist in the stale committed output. That determines whether the fix belongs in `1rst2md.py` (renderer) or is just a matter of regenerating output.

## 3. Plan

### Step 1 — Establish a clean baseline (no code changes yet)
- Back up current `output_md/source` (git already tracks it; just note current commit).
- Run the full pipeline fresh in order: `1rst2md.py` → `2rename-files.py` → `3create-yaml-toc.py` → `5clean-markdown.py`.
- Run `4fix-tables-without-header.py` against the fresh output and compare the count/kind of broken tables to the 29 found in stale output.

### Step 2 — Fix confirmed defects
Based on Step 1 findings, expect up to two fixes:
- **If the renderer still emits header-less/split tables** (e.g. from `list-table`/`csv-table` directives, or tables with `header-rows: 0`): `_render_table_as_markdown` in `1rst2md.py` already inserts an empty header row (`[""] * ncols`) plus a `---` separator when there is no `thead` — verify this path is actually reached for every table type in `input_rst`, including any RST tables docutils parses without a `tgroup`/`thead` in the shape assumed. Add a handler branch or normalize before parse rather than adding a fallback that hides bad output.
- **Fix the false-positive detector**: update `4fix-tables-without-header.py` to skip fenced code blocks, reusing the same fence-tracking helper pattern already in `5clean-markdown.py` (`_apply_outside_fenced_code_blocks`), so it doesn't flag code containing `|`.
- Do not add speculative handling for table shapes that don't occur in `input_rst` — confirm via Step 1 output before writing new branches.

### Step 3 — Regenerate output safely
- Re-run the full pipeline against `input_rst` to produce the final `output_md/source`.
- Re-run `4fix-tables-without-header.py` — expect 0 real broken-table blocks (ignoring any that are legitimately not GFM tables).
- Build the MkDocs site (`output_md/mkdocs.yml` / `build_mkdocs.bat`) to confirm HTML output renders correctly and nothing else regressed (broken nav, dead links, stripped content).

### Step 4 — Add automated tests
No test suite currently exists. Add `rst2md_converter/tests/` (pytest) covering:
- **Table rendering unit tests** against `1rst2md.py`'s `MarkdownRenderer`/`_render_table_as_markdown`: simple table with header, table with no header row, table with multi-line cell content (asserts `<br>` collapsing, not split rows), malformed grid table (mismatched widths) gets normalized.
- **GFM separator regression test**: run `find_markdown_tables_without_separator` (from `4fix-tables-without-header.py`) over freshly generated output and assert it returns an empty list — this is the regression guard for the original bug report.
- **Detector correctness test**: fenced code block containing `|` characters must NOT be reported as a broken table (covers the false-positive fixed in Step 2).
- **`5clean-markdown.py` unit tests**: `align_table_separator_rows` produces correct dash widths; `convert_table_break_bullets_to_asterisks` only touches table rows.
- **End-to-end smoke test**: run the full pipeline on a small fixture RST tree (2-3 files including one with a table) into a temp dir, assert output `.md` exists, has valid GFM tables, and MkDocs `nav` is generated.

### Step 5 — Guardrails against breaking downstream HTML
- Run tests in CI (or at minimum, locally before each pipeline run) so the "should not break anything" requirement is enforced automatically instead of by manual review.
- Keep `1rst2md.py`'s existing `conversion_report.json` and `validate_internal_links` checks as part of the standard run; fail the run (non-zero exit, already implemented) on unresolved refs/missing anchors/table fallbacks so regressions are caught before publishing.

## 4. Non-goals / things not to change
- Not rewriting the renderer architecture (Sphinx doctree → custom `MarkdownRenderer`) — it's sound, targeted fixes only.
- Not changing the `STRIP_*` content-stripping config flags at the top of `1rst2md.py` unless a test proves they cause the table defect.
- Not touching `2rename-files.py` / `3create-yaml-toc.py` unless Step 1 shows they interact with the table issue (unlikely — they don't touch table content).
